# Роль: Менеджер

## Завдання
- розбити вимоги методички на окремі Issues;
- визначити порядок виконання та назви гілок;
- стежити, щоб кожна зміна проходила через Pull Request із `Closes #N`.

## Що запропонував ШІ
- перелік Issues для рівнів 1 і 2 та їхні описи;
- шаблони опису Pull Request і Issue-дефекту;
- послідовність: Issue → гілка → коміт → Pull Request → merge.

## Що перевірив і прийняв автор
Номери Issues і Pull Request-ів звірено з реальними на GitHub.
