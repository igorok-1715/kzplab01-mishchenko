## 1. Тема, номер і варіант

- **Дисципліна:** Кросплатформні засоби програмування
- **Тема:** Розгортання Java-проєкту та базова обробка даних

## 2. Мета роботи

Пройти шлях від створення репозиторію до консольної програми, яку можна відтворено зібрати й запустити на Windows, macOS та Ubuntu.

Досягнуто:

- створено публічний GitHub-репозиторій із базовими службовими файлами (`.gitignore`, `.gitattributes`, `.editorconfig`);
- реалізовано читання, перевірку й обробку записів про посилки;
- обчислено чотири показники варіанта 15;
- сформовано звіт, який виводиться в консоль і записується у файл;
- налаштовано Maven-проєкт: JUnit 5, SpotBugs, виконуваний JAR, Maven Wrapper;
- підготовлено GitHub Actions для трьох операційних систем.

## 3. Постановка задачі

**Формат запису** (поля розділені `;`, файл у UTF-8, без заголовка):

```text
id;weightKg;city;deliveryDays;express
```

| Поле | Тип | Правила перевірки |
|------|-----|-------------------|
| id | String | не порожнє |
| weightKg | double | число з крапкою, не від'ємне |
| city | String | не порожнє |
| deliveryDays | int | ціле число, не від'ємне |
| express | boolean | лише `true` або `false` |

**Чотири показники варіанта 15:**

1. кількість коректних записів;
2. середня вага (кг);
3. найбільший термін доставлення (дн.);
4. кількість експрес-доставлень.

Хибний рядок не завершує програму аварійно: він пропускається, а в звіті вказано номер рядка та причину. Хибний рядок не впливає на показники.

## 4. Структура програми

```text
src/main/java/ua/lpnu/kzp/
├── Main.java          — точка входу, розбір аргументів
├── FileReport.java    — читання та запис файлів (Path, UTF-8)
└── ParcelReport.java  — перевірка, обчислення, формування тексту звіту
```

**Потік даних:**

```text
data/input.csv
      ↓  FileReport.readLines
  List<String>
      ↓  ParcelReport.buildReport
 (перевірка → перетворення → обчислення → текст звіту)
      ↓
    String report
   ↙          ↘
консоль   FileReport.writeReport → out/report.txt
```

Логіка обчислення не дублюється: один метод `buildReport` формує текст, який потім виводиться у два місця.

**Параметри командного рядка:** `--help`, `--version`, `--input <файл>`, `--output <файл>`. За замовчуванням вхід `data/input.csv`, вихід `out/report.txt`.

## 5. Інфраструктура

**Maven (`pom.xml`).** Координати `ua.lpnu.kzp:lab01:1.0.0`, `maven.compiler.release` = 21, кодування UTF-8.

| Компонент | Версія | Призначення |
|-----------|--------|-------------|
| junit-jupiter | 5.12.2 (scope `test`) | тести |
| maven-compiler-plugin | 3.13.0 | компіляція |
| maven-surefire-plugin | 3.5.2 | запуск тестів |
| spotbugs-maven-plugin | 4.9.7.0 (фаза `verify`) | статичний аналіз байт-коду |
| maven-shade-plugin | 3.6.0 (фаза `package`) | виконуваний JAR із залежностями |

**Версія.** `Implementation-Version` у маніфесті JAR береться з `${project.version}`, її виводить `--version`.

**GitHub Actions** (`.github/workflows/ci.yml`): матриця `ubuntu-latest`, `windows-latest`, `macos-latest`, JDK 21 (Temurin) з кешем Maven, виконання `./mvnw -B clean verify` (на Windows `mvnw.cmd`), публікація JAR як артефакту з назвою `jar-<ос>-<номер запуску>`.

## 7. Приклади роботи

**Вхідні дані** (`data/input.csv`):

```text
P001;2.5;Львів;2;true
P002;10.0;Київ;4;false
P003;0.8;Одеса;3;true
P004;abc;Харків;5;false
P005;-3.0;Дніпро;2;true
;4.0;Львів;3;false
P007;1.5;Львів
P008;3.2;Тернопіль;3;maybe
```

Три перші рядки коректні, п'ять останніх перевіряють різні види помилок.

**Консольний вивід:**

```text
Коректних записів: 3
Середня вага: 4.43 кг
Найбільший термін: 4 дн.
Експрес-доставлень: 2
Помилок: 5
Рядок 4: числове поле має помилковий формат
Рядок 5: від'ємне числове значення
Рядок 6: порожній id або місто
Рядок 7: очікується 5 полів, отримано 3
Рядок 8: express має бути true або false
```

**Файл звіту** `out/report.txt` містить той самий текст у UTF-8.

**Перевірка середньої ваги:** (2.5 + 10.0 + 0.8) / 3 = 13.3 / 3 ≈ 4.43.

**Запуск `--version`:**

```text
lab01 1.0.0
```

**Нюанс Windows.** У консолі з кодуванням за замовчуванням літера «і» могла відображатися як `?`. Файл звіту при цьому був коректним, бо записується в UTF-8. Вирішено командою `chcp 65001` перед запуском.

## 11. Відповіді на контрольні питання

1. **Призначення `pom.xml`.** Це опис Maven-проєкту: координати, версія Java, кодування, залежності й плагіни. За ним Maven знає, як компілювати, тестувати, перевіряти й пакувати програму.

2. **`test`, `verify`, `package`.** `test` компілює й запускає тести. `verify` виконує все попереднє та додаткові перевірки (у нас SpotBugs). `package` після цього створює JAR.

3. **Maven Wrapper.** Скрипти `mvnw` і `mvnw.cmd` завантажують потрібну версію Maven, тому на кожному комп'ютері не потрібна однакова глобальна установка.

4. **Метод `main`.** Це точка входу: з нього JVM починає виконання програми.

5. **Примітивний тип проти `String`.** Примітив (`int`, `double`, `boolean`) зберігає саме значення. `String` є посилальним типом: змінна містить посилання на об'єкт із текстом.

6. **Середнє в `double`.** Ділення двох `int` відкидає дробову частину. Приведення `(double) total / count` зберігає її.

7. **`Integer.parseInt("abc")`.** Метод кидає `NumberFormatException`, бо рядок не є числом. У програмі його перехоплюють на рівні одного рядка.

8. **Чому не можна мовчки пропускати помилку.** Користувач має знати, чому запис не потрапив до розрахунків, тому виводиться номер рядка й причина.

9. **`split(";", -1)`.** Від'ємний другий аргумент зберігає порожні поля наприкінці рядка, тому кількість полів визначається правильно.

10. **`Path.of`.** Він сам підставляє правильний роздільник для Windows, macOS та Ubuntu, на відміну від жорстко записаного `"data\\input.csv"`.

11. **Явний UTF-8.** Стандартне кодування залежить від системи. Явне UTF-8 гарантує однакове читання українських символів скрізь.

12. **`%n` та `\n`.** `%n` дає роздільник рядка поточної ОС (`\r\n` у Windows, `\n` в Unix), а `\n` завжди один символ.

13. **Що перевіряється у варіанті 15.** Кількість полів (5), непорожні `id` та `city`, `weightKg` як невід'ємне число, `deliveryDays` як невід'ємне ціле, `express` лише `true` або `false`.

14. **Тести для середнього.** Тест із кількома записами та відомим результатом: вага 2.5, 10.0 та 0.8 дають середнє 4.43. Також тест без коректних записів, щоб не було ділення на нуль.

15. **Статичний аналізатор.** SpotBugs шукає потенційні дефекти в байт-коді без запуску програми та зупиняє збірку, якщо знаходить проблему.

16. **GitHub Actions.** Автоматично збирає й перевіряє кожну зміну на Windows, macOS та Ubuntu та публікує JAR як артефакт.

17. **Issue на дефект.** Опис, кроки відтворення, очікуваний і фактичний результат.

18. **Розділ про доброчесність.** Інструмент ШІ, ролі, запити, прийняті рекомендації, виправлені помилки та підтвердження, що автор розуміє весь код.

19. **DevOps і Валідатор.** DevOps допомагає з Maven, аналізатором, JAR і Actions. Валідатор складає перелік крайових випадків, перевіряє результати й оформлює дефекти.

20. **Найскладніший рядок.** `String[] f = line.split(";", -1);`: від'ємний аргумент `-1` не очевидний, але без нього порожнє останнє поле зникло б і кількість полів рахувалася б неправильно.

Створено першу версію консольної програми для обробки даних про доставлення посилок: вона читає записи з UTF-8 файлу, перевіряє їх, пропускає хибні з поясненням, обчислює чотири показники варіанта 15 і виводить звіт у консоль та файл. Налаштовано Maven з JUnit 5, SpotBugs і виконуваним JAR, а також CI на трьох ОС.

Цей проєкт стане основою для лабораторної роботи № 2, у якій рядкові записи буде замінено власним класом `Parcel` без зміни зовнішньої поведінки програми.
